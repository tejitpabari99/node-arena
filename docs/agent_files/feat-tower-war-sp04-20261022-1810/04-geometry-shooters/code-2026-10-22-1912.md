## Measured optimizations

Initial isolated source-adapter benchmark failed: stress mean **1.1567 ms**, geometry mean **1.5331 ms**. Profiling identified repeated candidate/motion calculations, CJS live-export getter overhead and allocation pressure. Approved narrow changes:

1. Prepare per-channel motion/range rows once after head-on combat. Skip uniform-friendly pairs and whole-channel bounds before scanning; iterate ordered rows without per-pair filter arrays.
2. Cache rounded endpoints lazily only for rows entering interaction windows; reject disjoint swept coordinate bounds before sequence lookup. Recheck liveness before exchange.
3. Reuse private, per-state/per-channel scratch rows, motion, metadata and point storage. Reset endpoint readiness every tick; remove fully retired empty undrawn channels. No scratch enters snapshots/hashes or the public wrappers.
4. For entirely unclamped motion, certify contacts using rounded-endpoint swept quadratics. Each troop coordinate interpolation has <1 milli error; relative error is <2 per axis and Euclidean error <sqrt(8)<3. Rounded minimum <=r−3 certifies contact; >r+3 certifies no contact. The uncertainty band, clamped motion, unsafe coefficients and small-radius inner bound retain the exact rational solver. Discriminant products use existing exact factored Number comparison; no hot BigInt/floating distance.

Targeted tests cover oblique/fractional progress, r±1/2/3, radii 0–3, fresh/end-clamped motion, mixed-owner defensive handling, death/refill, real capture/cut/redraw, new owners/kinds, independent state scratch and the existing 50-seed brute-force BigInt oracle.

A six-trial native GC diagnostic found no >0.75 ms steps or GC in measured windows; one minor GC occurred in an excluded JIT warmup. No GC forcing was introduced. Short diagnostic p99 was variable; acceptance uses the full unchanged benchmark.
