# Task 1 — Package scaffold + TypeBox spike

Branch: `feat/game-design`. Workspace: existing `.worktrees/feat/game-design` (kept per explicit user instruction). Scope: SP01 task 1 only; TASKS.md belongs to the orchestrator and was neither read for scope nor staged.

## Outcome

**Keep TypeBox (Decision 1).** `typebox@1.3.36` builds a Draft-07 JSON Schema directly, infers `Troop` with `Type.Static`, and compiles in `ajv@8.20.0` with `strict:true` and `allErrors:true`. The emitted schema validates the actual `data/troops/regular.json` sample and rejects unknown fields, malformed ids, invalid numeric ranges, fractional value, unsupported schema versions, and missing `$schema`. A build-time negative type assertion proves the inferred type rejects string-valued speed.

The shared Ajv registers `x-unit` and `x-presentation` metadata explicitly without disabling strict mode. Unknown schema keywords still throw. Invalid payloads report every failing field through Ajv's JSON-pointer errors, and validation neither coerces nor removes input fields.

`src/index.ts` exports `TroopSchema`, `Troop`, `SCHEMA_VERSION` (`1.0.0`), `createAjv`, and `validateTroop`. `pnpm content:schemas` generates the committed editor schema; `pnpm check:schemas` compares its complete output. Node I/O exists only in the generation script and tests.

ESLint bans bare and `node:` fs/path/crypto imports, subpaths, re-exports, literal dynamic imports, and CommonJS require throughout `packages/content/src/**/*.ts`, covering future loader/validator/compiler/hash filenames and nested modules. Tools and tests may use Node I/O. This is a source import boundary, not a security sandbox for computed module names.

Primary references: [TypeBox types and JSON Schema](https://github.com/sinclairzx81/typebox), [Ajv strict and validation options](https://ajv.js.org/options.html), [ESLint restricted imports](https://eslint.org/docs/latest/rules/no-restricted-imports).
