# SP03 Task 2 — Instanced-troop performance spike

## Decision

**GO** for Decisions 1/2: one `InstancedMesh` per visual × team, packed `(x,z,yaw,phase)` attribute, patched `MeshStandardMaterial` with procedural bob/sway. At 2,000 total troops, measured bob JS p95 = **1.1 ms**, maximum = **2.4 ms**, **4 draw calls**, **120,000 triangles**. Both automated gates pass: JS <4 ms and draws <100. This is permission to proceed with renderer implementation; integrated-GPU 60 fps/readability acceptance still needs the owner's laptop.

The frozen `static-bob` variant keeps a phase-dependent pose; `none` disables bob/sway while retaining placement/yaw. Neither fallback consistently improves this software-fps sample, so keep animated bob. Use `none` for reduced motion and as the first performance fallback if the actual laptop/art scene fails; static-bob is available for a frozen pose. VAT remains deferred: this spike provides no evidence that its additional asset/texture pipeline is needed. If authored art cannot read well with procedural motion, reassess VAT independently of this CPU result.

## Harness and method

- Separate production-built `/spike.html?mode=bob|static-bob|none`; `src/dev/spike/` is isolated from the main entry and production renderer. Vite has two HTML entries.
- 2,000 troops **total**, divided equally into two visual proportions × two teams (500 per mesh), all visible in separate marching lanes. Each capsule is 60 triangles, below the 300/troop budget. No production art, ground, sim, shadows or post-processing. Perspective camera; ambient + directional lights; standard lit opaque materials.
- Fixed 640×360, DPR 1, antialias off. Primitive differences are proportions; team colours are uniforms. Identity instance matrices; only the packed float attribute updates each frame, with dynamic usage, no per-troop objects/matrices created. Patched positions and normals both rotate with sway/yaw. Troops do not cast shadows; culling disabled.
- Chromium 156.0.8078.4, Three r186, ANGLE Vulkan 1.3.0 **SwiftShader Device (Subzero)** on Linux KVM, AMD EPYC-Rome, four virtual CPUs. Playwright desktop user agent reports Windows, but host is Linux. Concurrent manifest implementation ran on the same host.
- Each mode: 30 warmup rAF frames, then 120 JS samples and 119 intervals between measured rAF starts. One serial browser run per mode, nearest-rank median/p95. CPU clock quantization (~0.1 ms) explains zero update samples. All recorded samples, including long frame intervals, are retained.
- `updateMs` times the attribute write loop plus frame clock update. `renderSubmissionMs` times the synchronous `renderer.render` call. `jsMs` covers their combined wall duration. It can include driver work/blocking; it is **not** a GPU timer. No `gl.finish` contaminates the CPU metric. `frameMs` and average fps measure rAF pacing and therefore include software rendering/driver/scheduling delays. They cannot isolate software raster time or prove laptop fps.
