## Task 1 - Probe tags and `visualProbe()` + harness hooks
What it is / what it means: The projection-first metric source (Architecture: Probe; Decision 3). Test hooks only, absent in prod build.
What changes at a high level: Add tag-only `userData.visualRole` (tower, count, lane, troop, ground; lane also `pair`) in the v1 towers/lines/troops/scene renderers, with no look change. Add `window.__na.visualProbe()` returning the plain-JSON shape in the PRD, built from existing `inspect()` handles and the camera `project()`. v1 gaps (floors, splitScreen, ribbon width) return null. Add `ground.playQuadScreen` (projected grass-patch quad, null on v1) to the probe. Add harness support for an optional `seed` on `load` and `render({settle})` (default true) calling each renderer module's optional `settle()`; renderer-local state timers (springs, pops, build-outs) use a fixed dt per stepped tick. World time needs no change: `apps/web/src/app/runtime.ts:86` already derives it from `(tick + alpha) / TICK_RATE`, so no look-changing renderer edit is made (PRD Decision 2).
Done when: unit tests cover probe shape, null-for-gaps, and absence in prod build; existing unit tests unchanged-green.
Iteration: Non-visual tooling. Self-check: `pnpm --filter @node-arena/web test` then call `visualProbe()` twice on the same stepped state; JSON must be identical. Log each attempt as a row in BF/01-visual-qa-harness/iteration-log.md. Loop: change, re-run touched tests, commit if green, revert if a prior test breaks. Stuck rule: 3 iterations with no progress, write hypotheses to the log and switch approach. Cap 12; then mark `blocked`. Never delete tests.

## Task 4 - Pixel helper + `visual:selfcheck` (determinism loop)
What it is / what it means: Acceptance criterion for same-machine byte-identical output; shared pixel helper (second blank page, PNG to canvas to getImageData).
What changes at a high level: `lib/pixels.mjs`, `lib/lint-determinism.mjs` and `selfcheck.mjs` (capture x2, compare SHA-256 of every PNG; fallback <=0.01% differing pixels with channel delta <=2 and metrics.json identical after dropping `perf`). The lint greps `apps/web/src/render/**` and `apps/web/src/fx/**` for `Math.random|crypto.getRandomValues|Date.now|performance.now` (allow-list: perf sampling, test-harness) and selfcheck fails on any hit; render jitter must be seeded from `(pairKey, tick)` with a mulberry32 helper (N6). Also add the same rule to the eslint config as `no-restricted-properties` if the config supports it without touching other rules.
Done when: `visual:selfcheck` is green on two consecutive runs, and a deliberately inserted `Math.random()` in a render file makes it fail (then remove it).
Iteration: Command: `pnpm --filter @node-arena/web visual:selfcheck`. Target: identical hashes. On any diff, find the source (clock, font, MSAA, shader time uniform, DOM transition), log it in iteration-log.md (iter #, date, commit, diff count, hypothesis, change), fix, repeat. Stuck rule: 3 iterations with no change in diff count, write hypotheses, switch approach (e.g. pin `quality:'low'` no-AA for capture). Cap 12, then `blocked` and proceed.

## Task 8 - Iteration-0 baseline + calibration + regression gate
What it is / what it means: Iteration protocol steps 3-5; Decision 9. Proves the harness discriminates.
What changes at a high level: On unmodified v1 visuals run capture and compose, view all composites, score every V01-V24 0-10 against its anchors (self score, blind scorer via `visual:score-sheet`, min via `visual:score-merge`; >=3 logged differences before any score >=8), evaluate M01-M20, and write row 0 to iteration-log.md (iter #, date, commit, per-item scores, metrics, top 3 gaps, planned change). Expected: most items <=3, M01, M02, M03, M05, M06, M07, M12 fail. Anything passing at baseline gets a tightened anchor or threshold. Calibration per PRD step 4: (a) `visual:calibrate` passes every pixel metric on towerwar_01 and yt1 (fix the metric, never the ref); (b) the hand-built landscape mock `visual/calib/mock-landscape.html` passes M09/M10/M14; (c) score `towerwar_01.jpg` as a capture for V01-V13, every item >=8; (d) blind-scorer discrimination controls: `v1_playtest_1.png` <=4 on V01-V07 and V22, `citytakeover_01.jpg` <=6 on V05 (tighten anchors if not). Confirm or fix every `prov` threshold and mark it `cal`. Record calibration.
Done when: row 0 logged with all items and scenes; calibration recorded; `pnpm --filter @node-arena/web test`, `typecheck`, `lint`, `test:e2e` unchanged-green with no e2e file or snapshot modified.
Iteration: Visual-style loop. Commands: `pnpm --filter @node-arena/web visual:capture`, `visual:compose`, `visual:check`. Compare against refs per ref-map. Gated items: all V01-V24 scored under the Scoring protocol; metrics M01-M20 per `thresholds.json`. Loop: capture, compose, view, score, fix rubric or thresholds (tighten only) on top 1-3 discrimination or calibration gaps, re-run touched tests, commit if improved, revert if worse. Exit: baseline discriminates, calibration (a)-(d) recorded and passing, tests green. Stuck rule: 3 iterations with no improvement, log hypotheses, switch approach. Cap 12, then mark `Blocked-visual` here and continue. Never edit refs or delete tests.
