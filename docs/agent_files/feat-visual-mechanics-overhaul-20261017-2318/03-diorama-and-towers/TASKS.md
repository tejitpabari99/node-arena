Loop: capture, compose, view the `visual-out/compare-<scene>.png` composites yourself, score gated items 0-10 against the anchors under the protocol, read metrics, fix only the top 1-3 gaps with the smallest change, re-run touched unit/e2e tests, commit (`03-diorama-and-towers: Task N - iter k: <change>`) if improved, revert if any merged score dropped. Metric ids M01-M20 are defined in SP01 PRD (HSV colour spec); this file never redefines them. Stuck: 3 iterations with no improvement, log hypotheses and switch approach. Cap 12 iterations, then mark `Blocked-visual` in this file and continue. Never edit refs, lower thresholds, delete tests or update screenshot baselines. ## Task 4 - Instanced stacked tower meshes (white floors, team roof/bands)
What it is / what it means: R7 (mesh part), Decision 6, N5. Reproduces the Tower War tower pattern measured from the refs and builds it instanced from the start so the draw budget holds.
What changes at a high level: Code-built `tower-mesh.ts` with the exact pattern seen in towerwar_01 (red 5, blue 5, yellow 4, grey 25), towerwar_03/06 and the yt1 zooms: bottom to top, team-colour octagonal plinth with a light-grey chamfer trim ring, light-grey door frame + dark door + two side buttresses; 1-5 floors, each a chamfered octagon body in white/light grey (`#E6E8EA`) with one dark horizontal slit window, standing on a thin chamfered team-colour band (white / team band / white / team band rhythm), upper floors ~4% narrower; a thick chamfered octagon roof cap in the saturated team colour overhanging the top floor. Floor bodies are never team-painted (City Takeover look is wrong); only roof cap, bands and plinth take the team hue; neutral = all grey (roof `#8C8C8C`, bands `#C0C0C0`, bodies light grey, no saturated pixels). One `InstancedMesh` per material across all towers (body-white, band-team, roof-team, plinth-team, trim-grey, dark-detail) with `instanceColor` for team materials and 5 reserved floor instances per tower (hidden floor = zero-scale matrix; 150 ms pop and 250 ms capture pop animate instance matrices); tower roots are empty groups. Floors = `clamp(ceil(5 * count / cap), 1, 5)`. Archetype width from `footprintRadius` x ~0.9. Sets `userData.visualWidth` and `visualRole='tower'` (+ `userData.towerIds[]` on the instanced meshes) so SP01's probe derives model rects from root transform + `visualWidth`; `towers.visualWidth(id)` returns it. Probe fields `floors`, `visualWidthWorld` become non-null. Tune footprint scale, not camera.
Done when: floor-band function table unit test passes (caps 20/50/80 each span 1-5); `visualWidth` contract unit-tested; draw-budget unit test builds 14 towers and asserts <= 8 meshes/draws added regardless of count; neutral towers have no saturated pixels in a capture crop.
Iteration: Visual. Scenes: `l01` at 1920x1080 and 1366x768, then `l10`. Refs: `towerwar_01.jpg` (red5, blue5, yellow4, grey25 crops), `towerwar_03.jpg`, `towerwar_06.jpg`, `towerwar_yt1.jpg` (floors, zoomed "38"/"44"). Gated items: V05, V06. Metrics: M01 standard tower width >= 6.0% at 1920x1080 and >= 5.5% at 1366x768, M04 floors 100%, M11 (team-hue share of saturated pixels >= 0.85, team-sat/fg 0.35-0.72 and never >= 0.80, white body 0.15-0.45; neutral all grey), M18(ii) tower-crop palette distance <= 0.20, M20 floor stripes, M13 drawCalls <= 100 on l18 (towers add <= 8).
