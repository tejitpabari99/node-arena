# PRD: SP03 — Diorama + Towers
Repo/branch: node-arena · `feat/visual-mechanics-overhaul` · Depends on: SP01 (capture/compose/checklist) · Owns: `apps/web/src/render/{scene,camera,towers,ground,props,tower-mesh,roof-texture}.ts`, `render/overlays.ts` (registry kept; label/slot-glyph consumers removed), deletes `render/labels.ts`, `apps/web/src/test-harness/index.ts` (label-reading lines only; SP01 owns the probe), `apps/web/assets/manifest.json` (themes/camera/visuals/palettes), new prop GLBs, `tools/assets/import-art.mjs` (nature pass), `docs/CREDITS.md`, tower/scene e2e specs.

## TL;DR
Replace the grey plane, void, road slab and floating cards with a look that matches the reference images (`ref/towerwar_*.jpg` primarily) as closely as possible (same camera feel, proportions, palette, tower shapes, number/dot style, lane look, troop look, props, HUD): ~65° camera fitted to the level, bright grass patch inside a sand border dressed with trees/rocks/crates and rock cliffs, one soft-shadow light, saturated team palette. Towers become code-built stacked-floor octagonal blocks with the Tower War look measured from the refs (white/light-grey stone floors with slit windows, thin team-colour band under every floor, thick team-colour roof cap and plinth; neutral all grey), a white outlined count and 1–3 slot dots on the roof, drawn instanced across towers so the draw budget holds. Ships on L1 first; L10/L18 only smoke-checked (SP05 rolls out).

## Problem
[verified: v1_playtest_1.png] grey plane in light-blue void, road slab hanging off it, label cards ~3× tower size, tiny grey towers. [verified: assets/manifest.json] the "road" is not scene code: every `city.*` theme lists six `prop.road` entries at x=10..110, z=-8 (authored for a different coordinate frame; level towers sit around origin, bounds 120×80 = ±60×±40) plus lights and cones. [verified: scene.ts] ground = a plane sized to tower bounds; camera `pitchDeg 55, fov 45, margin 12` in manifest; labels = DOM chips (`render/labels.ts`, 96 px wide) projected every frame.

## Goals / Non-Goals
Goals: steep camera, no void/board edge at 16:9 and 16:10; ground and prop border matching the Tower War refs; towers ≥ 6% viewport width, roof count readable at 1366×768; colourblind glyph on roof; labels gone; theme stays data.
Non-goals: lanes/troops/clash (SP04), HUD/menus/rollout/baselines (SP05), tower types beyond small/standard/large, extra themes (→ `docs/FUTURES.md`), level layout edits, sim changes.

**R7 Towers.** Code-built `tower-mesh.ts` reproducing the pattern **measured from towerwar_01 (red 5, blue 5, yellow 4, grey 25), towerwar_03, towerwar_06 and the yt1 zooms of "38"/"44"** (full description in SP01 CHECKLIST "Tower look"). Bottom to top: (1) wide octagonal *plinth in the team colour* with a light-grey chamfer *trim ring* on top, a light-grey *door frame* with a dark door and two small side buttresses; (2) 1-5 *floors*, each a chamfered octagon **body in white/light grey** (`#E6E8EA`) with one dark horizontal *slit window*, standing on a **thin chamfered team-colour band**, so the rhythm reads white body / team band / white body / team band; each upper floor ~4% narrower than the one below (stepped taper); (3) a **thick chamfered octagon roof cap in the saturated team colour** overhanging the top floor (flat top, darker bevelled edge). **Only roof cap, bands and plinth carry the team hue; the floor bodies are never team-painted** (whole-tower paint is the City Takeover look and is wrong here; this reverses the earlier "body + roof in team colour" wording). **Neutral = all grey**: roof `#8C8C8C`, plinth/bands `#C0C0C0`/`#8C8C8C`, bodies light grey, no saturated pixels. Flat-shaded `MeshStandardMaterial`, floor height ~0.9 u. Width from archetype: small/standard/large footprint radius (`footprintRadius` x~0.9). **Draw budget (N5): built instanced from the start.** One `InstancedMesh` per material across **all** towers (body-white, band-team, roof-team, plinth-team, trim-grey, dark-detail for slits+door) with per-instance colour (`instanceColor`) for team materials, 5 floor instances reserved per tower (hidden floors = zero-scale matrix, pops animate the instance matrix), plus one instanced roof-decal mesh sampling a single 512x512 atlas (4x4 cells of 128x128, one cell per tower, <= 16 towers); all tower geometry therefore costs <= 8 draw calls independent of tower count (a unit test builds 14 towers and asserts <= 8 meshes added), keeping M13 drawCalls <= 100 with shadows on. Tower logical roots are empty `Group`s (no draw) carrying `userData.visualRole='tower'` and `visualWidth`. **Contract for SP04/SP01:** `tower-mesh.ts` sets `userData.visualWidth` (world u, across-flats incl. scale) on each tower root and `towers.visualWidth(id)` returns it (SP04 lane width = 0.33 x mean of endpoints); instanced meshes carry `userData.visualRole='tower'` / the decal mesh `visualRole='count'` plus `userData.towerIds[]` (instance -> tower id), and SP01's probe derives each tower's model Rect from the root transform + `visualWidthWorld` + stack height instead of mesh traversal; probe fields `floors`, `cap`, `countOnRoof`, `slotDots`, `visualWidthWorld`, `hasCard=false` must be non-null. Screen width >= 6% of viewport (standard); tune `footprint` scale, not camera.
*Floor bands* (cap-relative so small cap 20 / standard 50 / large 80 each span 1-5): `floors = clamp(ceil(5 x count / cap), 1, 5)` (ref check with TW cap 63: 5 -> 1, 25 -> 2, 38/44 -> 4, Max -> 5). Floors are shown/hidden (not rebuilt); gaining a floor does a 150 ms scale-pop. Capture: recolour + 250 ms pop (scale 1 -> 1.12 -> 1) on owner change.
*Roof decal*: per-tower 128x128 canvas (SRGB) drawn only on text/dots/glyph change and blitted into that tower's atlas cell (mipmapped atlas, anisotropy 4); text = bold sans 72 px, white fill, black 8 px stroke (outlined like TW), drawn flat on the roof plate in its upper half, digit height ~0.16-0.22 of tower width (M02), so it foreshortens with the tilt. Canvas chosen over SDF text: no font dependency, redraw only on change. "Max" when `count >= cap`.
*Slot dots (N3, decided from evidence)*: dot count = current `slots` (1 below 10 troops, 2 from 10, 3 from 30 = `extraSlotAbove`; refs: grey 25 shows 2, "38"/"44" show 3). Row of round dots below the number, diameter ~0.12-0.15 of roof width. **Bright opaque white = free slot; dim translucent (~35% white over the roof) = slot in use by an outgoing line** (dot state = slots - lines). Evidence [verified by viewing and pixel crops]: towerwar_01 blue 5 (no outgoing line) and neutral grey 4/grey 25 show bright dots; red 4, red 5, yellow 4 (each with a line out) show one dim dot; towerwar_yt1 "44" shows two bright + one dim (it has one visible outgoing line), "38" shows three dim (several lines leave it). `ref/REFERENCE.md` ("filled white = free, translucent = in use") is therefore correct and the earlier SP03 text ("filled = used") was wrong. Also **neutral towers show their bright dots** (refs do), even though a neutral cannot draw; correction to REFERENCE.md (not edited): it says the count floats "ABOVE tower top", but in every ref the number sits **on the roof plate**, and its "1 tier ~lvl<10 ..." floor rule is replaced by the cap-relative band above.

## Architecture
```
manifest.themes.grass ─▶ scene.ts ─▶ ground.ts (sand plane, grass patch, rocks)
                                   ─▶ props.ts  (seeded scatter → InstancedMesh)
                                   ─▶ light/clear colour
manifest.camera + level bounds ─▶ camera.ts fitCamera (towers only)
SimView ─▶ towers.ts ─▶ tower-mesh.ts (floors) + roof-texture.ts (canvas) ; no DOM labels
```
`towers.update(view, {colorblind})` keeps its signature; it now diffs `(owner, count, cap, slots, lines, colorblind)` per tower and only then repaints/rebuilds floor visibility. Scatter takes `(levelId, bounds, towers[], theme)` and returns instance matrices — pure, unit-testable.

## Iteration protocol
Visual loop per task with a visual outcome:
1. Capture: `pnpm --filter @node-arena/web visual:capture [--scene <id>]` — deterministic (fixed seed, paused at fixed tick, 1920×1080 and 1366×768); PNGs + `metrics.json` to `apps/web/visual-out/` (git-ignored).
2. Compose: `pnpm --filter @node-arena/web visual:compose` → `visual-out/compare-<scene>.png` (current | reference).
3. Score under the **Scoring protocol** (SP01 PRD; mechanics `visual:score-sheet` / `visual:score-merge`): view each composite and score every task-relevant item of `<BF>/01-visual-qa-harness/CHECKLIST.md` 0–10; before any score ≥ 8 log ≥ 3 concrete observable differences vs the ref (what, ref value, ours); the item's mapped pixel metric (CHECKLIST "Pixel check") must pass for ≥ 8; then spawn a fresh blind scorer sub-agent that sees only the composite PNG(s) and the blank `visual:score-sheet` (no code, metrics, log or earlier scores); merged item score = min(self, blind) via `visual:score-merge`. Read `metrics.json` against thresholds.
4. Log: append to `<BF>/03-diorama-and-towers/iteration-log.md`: iter #, date, commit, self/blind/merged scores, difference log, pixel-check results, metrics, top 3 gaps, planned change.
5. Change only the top 1–3 gaps, smallest change; run unit/e2e for the touched area.
6. Commit each improving iteration: `03-diorama-and-towers: Task N — iter k: <change>`. Revert an iteration that lowers any score.
7. Exit: all task-relevant items ≥ 8 on the **merged** score AND metrics pass AND tests green. Stuck rule: 3 iterations without improvement → log hypotheses, switch approach (different asset/param/technique). Cap 12 iterations/task → mark `Blocked-visual` in TASKS.md with the log, continue.
8. Never edit reference images, lower thresholds, or delete tests. Screenshot baselines are updated only in SP05 (or when a task says so, with a logged reason).
9. SP05 compiles `final-review.md`.
