## Task 1 — Churn tool + committed v1 baseline
What it is / what it means: The headless metric that defines "bots keep changing nodes" (PRD R9, D6). Must exist and be baselined on unmodified code before any behaviour change, so targets are reproducible.
What changes at a high level: Add `pnpm bots:churn [--seeds N] [--levels …] [--out file]` backed by `packages/bots/scripts/churn.mjs`, exposed as **both** the `packages/bots` package script and a root `package.json` script `bots:churn` (root script currently absent). It runs all 20 levels x a fixed 8-seed list (hard-coded in the script, never changed) and counts per bot seat, from the command stream and the sim `LineCut` events: bot cuts, draws, LineCut events by reason (player/slots/captured/replaced), slot-cuts/min, cut-then-redraw on the same pair within 10 s (by reason and total, any reason), visible line flips per pair regardless of cause (cut/removal then redraw, or draw/cut/draw, within 20 s), normalised per minute of match time. If `runMatch` does not expose events, step the sim with events enabled or reconstruct cuts from per-tick line views. Prints per-bot and per-level tables plus JSON. Save output from unmodified code as `packages/bots/churn-baseline-v1.json`, and create the iteration log with a baseline row.
Done when: baseline JSON committed first, before any bot/schema change; log has baseline row (iter 0) incl. slot-cuts/min and LineCut-by-reason; `pnpm bots:churn` and `pnpm --filter @node-arena/bots bots:churn` (or equivalent package invocation) both run and print both tables and JSON.
Iteration: Tooling task. Self-check: run `pnpm bots:churn --out <tmpA>` twice on the same code and diff the JSON; must be byte-identical (deterministic). Also confirm the baseline file equals a fresh run on the commit it was generated from. Fix tool bugs (miscounted pair direction, time normalisation) and re-run the self-check; stuck rule: 3 iterations with no progress, log hypotheses and change approach; hard cap 12 iterations, then mark `Blocked`, log it, continue. Log row: iter #, date, commit, params (none), cuts/min, draws/min, cut-redraw/min, flips/min, notes.

Profiles lacking the block must behave exactly as v1. Regenerate schemas and content lock, bump `BOT_VERSION` 1.0.7 -> 1.1.0 and the content version per AGENTS.md.

## Task 3 — Bot enforcement of commitment
What it is / what it means: The behavioural fix for causes C1-C5 (R1-R6, D1-D3, D5, D7), enforced only in the bot.
What changes at a high level: In the utility bot, track bot-local line age as first-seen tick per (from, to, drawSeq) from the line view, dropping entries when a line disappears; reset per match; no new allocations in decide. Filter cut candidates: skip while younger than min lifetime unless source danger >= override (that source only); require noise-free cutScore minus keepScore (best attack/reinforce on that pair, noise-free) >= cut margin. After a pair is cut (own `CutLine` or a detected sim slot-cut: own line vanished, no own cut issued, source still owned, not replaced), block DrawLine on that unordered pair for the redraw window regardless of danger or stickiness. Slot guard: do not draw a line onto a slot gated by threshold `T` (from the tower archetype's `extraSlotAbove`) when `garrison − T < slotGuardMargin`; prefer a deliberate cut: when at capacity and `garrison − T ≤ slotPreemptMargin`, cut the lowest-keepScore own line from that tower (bypassing lifetime lock and cut margin) rather than letting the sim cut the newest line, which also stamps the redraw block. No `GAME_RULES.md` edit. Cuts use noise-free scores when the top candidate beats the best line-consistent option by less than tie hysteresis; draws keep noise. No extra RNG draws without commitment; document RNG consumption order.
Done when: bots with a `commitment` block apply all four rules plus the slot guard/pre-empt rules and the redraw block on slot-cut pairs; bots without it produce identical commands to v1; sim package diff empty; typecheck and lint pass.
Iteration: Non-visual. Measure: `pnpm bots:churn` vs `churn-baseline-v1.json` at PRD default params, plus `pnpm --filter` bots tests. Target for this task: total cut-then-redraw/min (any reason), slot-cuts/min and bot cuts/min all below baseline, no-commitment path identical to v1 (diff commands for a profile with block removed). Log row per iteration: iter #, date, commit, params, cuts/min, draws/min, cut-redraw/min and % vs baseline, flips/min, top gaps, planned change. Loop: measure, fix top 1-2 gaps, re-run touched tests, commit if improved, revert if any target metric worsens. Stuck rule: 3 iterations without improvement, log hypotheses, change approach (e.g. keepScore definition); cap 12, then `Blocked`, log, continue.

What changes at a high level: Add bots tests covering: slot-cut detection stamps the redraw block, slot guard refuses a draw within `slotGuardMargin` of a threshold, pre-emptive deliberate cut picks the lowest-keepScore line, lifetime lock and danger override (per source), cut margin versus keepScore, redraw block (including under danger and ignoring stickiness weight), noise-free cut on near-ties while draws stay noisy, age-map cleanup when a line is replaced, per-match state reset, and v1-equivalence for profiles without the block. ## Task 5 — Tune to churn targets, hold balance bands
What it is / what it means: The measured loop from the PRD's iteration protocol: reach the churn targets without moving balance bands (Goals, drift rule).
What changes at a high level: Tune only base-profile values, 1-2 params per iteration, in order: `minLineLifetimeSec`, `cutMargin`, `redrawBlockSec`, `tieHysteresis`, `dangerOverride`. If a band fails, first lower `cutMargin`/`minLineLifetimeSec` for the affected base profile only (expert variants share base values). Optional last step, non-gating: watch L10 at 2x for about 2 min (browser run by the executing environment) and log "no visible flip-flop" or the gap.
Done when: **total** visible cut-then-redraw (any LineCut reason) >= 80% below baseline; bot cuts/min >= 40% below; slot-cuts/min reported (secondary target >= 60% below); `pnpm validate:levels` passes; `pnpm balance` passes every band in unmodified `tools/balance-targets.json`; bots/content/tools tests green.
Iteration: Measure `pnpm bots:churn` on the frozen seed set vs `churn-baseline-v1.json`, then `pnpm balance` and `pnpm validate:levels`. Log row: iter #, date, commit, params, cuts/min, draws/min, cut-redraw/min and % vs baseline, flips/min, balance win rates per band, validate:levels pass/fail, top 3 gaps, planned change. Loop: fix top 1-2 gaps, re-run touched tests, commit each improving iteration as `02-bot-line-commitment: Task 5 — iter k: <change>`, revert any iteration that worsens a target metric or breaks a band. Exit: all targets above met and tests green. Stuck rule: 3 consecutive iterations without improvement, log hypotheses, switch approach (per-profile values, danger definition, keepScore definition). Hard cap 12 iterations, then mark `Blocked`, log, continue. Never edit `balance-targets.json`, never delete tests.
