## TL;DR
- **Rocket tower** (`rt`, 856 uses; position 216+): owner sets a persistent **aim point**; tower fires a stage-sized volley (1/2/3 rockets by level <10 / <30 / else) every `480000/(level+120)` ms; each rocket lands `rocketMoveTime` 1.0 s after launch (fixed time, not distance), blast radius 1.15, kills enemy troops, `level -= 3/4/5` on enemy buildings (never flips), destroys mines/ceils, damages walls. [decomp 03 §5.7]
- **Capture rocket** (`c_rt`, 251 uses; position 89+) — **owner redesign 2026-10-28 (binding; replaces the decoded TW charge model as shipped behaviour)**: the tower's **LEVEL is its charge**. Per-archetype `maxLevel` 100 (other buildings stay 64). Each arriving OWN troop adds +1 level (flat, all troop types); enemy troops damage it as normal. Passive growth +1.0 level/s while owned (non-neutral); neutral = no growth, no firing. On reaching `fireLevel` 100: 3 s windup (60 ticks, "armed" pulse in web; the level number is the meter, no new meter UI), then one shot, then level resets to `resetLevel` 10; no extra cooldown. No valid target: holds at 100 and fires (windup then) when one appears. Shot effect and targeting unchanged from decoded TW: target level -> 0 (no ownership change), enemy troops within 3.0 killed, ~2.0 s flight; target = highest-level enemy building, neutral only if no enemy qualifies, never own. All numbers are per-map overridable params (`fireLevel` 100, `resetLevel` 10, `chargePerTroop` 1, `growthPerSecond` 1.0, `windupMs` 3000); importer ignores TW `scp/mcp/cc`. Design rationale and fill times in Requirements (CRK-06). The decoded TW charge model is kept below as "TW reference (decoded)".
- New commands `Aim{player,from,x,z}` and `ClearAim{player,from}`; capture rocket is automatic (no command).
- Human UX: drag from owned rocket tower to ground (or tap tower, tap ground), reticle at radius 1.15, reload ring on tower. AI/proxy use the decoded `coefficientByRocketTowerAttack x level` argmax.
- Minor bump 3.5.0: no shipped level has rt/c_rt, 20 existing replays bit-identical.

## Problem
- `rocket`, `capture-rocket` rows are `archetype: null` (blocked) [verified: `feature-map.json`]; rt appears in 856 level uses, c_rt in 251, so these gate a large share of positions 89-340 [research 01 §3.1; 02 §5].
- Sim has no command that is not a line between two buildings: `parse()` accepts only `type, player, from, to` [verified: `packages/sim/src/commands.ts`]. The rocket aim is a point.
- Bots emit only `DrawLine` [verified: `tw-ai.ts`]; TW AI rocket logic (04 §3.4) and the validate:levels proxy have no hook, so rocket levels are unplayable by proxy.
- [decoded] TW keeps capture charge accounting in `CaptureRocketTowerUiView` (see "TW reference (decoded)"). Owner redesign (2026-10-28) replaces it with level-as-charge, which needs no separate charge state: the existing level is the meter and the sim state is only a windup timer + growth accumulator.

## Requirements
**R1 Rules (GAME_RULES first)**
- `RKT-01` aim: `Aim` sets/replaces the tower's aim point (milli ints, inside playfield bounds); persists until `ClearAim`, owner change, or disable. `RKT-02` volley cadence: first volley `defaultDelay*0.5` = 250 ms after the tower first has an aim and is ready; then `ceil(480000/(level+120))` ms, level sampled at fire time. `RKT-03` stage = 1/2/3 by level; one volley launches `stage` rockets (spacing (Risk 2)). `RKT-04` effect: closed-disc 1.15 blast at the aim point; enemy troops die; enemy buildings `level = max(0, level - [3,4,5][stage-1])`, no ownership change (R-ENT-05-style, level 0 still needs a soldier hit); mines destroyed, walls damaged, ceils destroyed (via 02/05 element hooks). `RKT-05` disable: a rocket tower brought to level 0 by a rocket-type projectile (rocket or capture rocket) is disabled 5.0 s: no volleys, `Aim` rejected, aim cleared (Risk 4). `RKT-06` rocket tower has no soldier lines (`DrawLine` -> `not-drawer`); grows/captured like a house.
- **Capture rocket tower, shipped behaviour (owner redesign, binding, 2026-10-28):**
  - `CRK-01` level is charge: archetype `maxLevel` 100 (per-archetype override; houses/others stay 64). Each arriving OWN troop adds `chargePerTroop` (default 1) level, flat for all troop types (not unit defense), clamped to `maxLevel`. Enemy troops damage/capture it exactly as for any building (lowers level; capture rules unchanged).
  - `CRK-02` growth: `growthPerSecond` (default 1.0) level/s while owner is non-neutral; none while neutral. Implemented as a dedicated fixed-rate param on the `captureRocket` module (not the existing `grows` module, so it is independent of building-level growth tables): accumulator in milli-levels, +50 milli/tick at 1.0 (= +1 level per 20 ticks at 20 Hz), carry kept, integer only. Growth stops at `maxLevel`.
  - `CRK-03` fire: when level `>= fireLevel` (100) and owner non-neutral, windup starts: `windupMs` (3000 = 60 ticks) countdown, web shows a visible "armed" pulse (existing level number is the meter; no new meter UI). At windup end, if a valid target exists, fire one shot and set level to `resetLevel` (10) at fire; no extra cooldown (growth/feeding resume immediately). If the level drops below `fireLevel` during windup (enemy hit), windup cancels and restarts when level is again `>= fireLevel`. Owner change cancels windup; level is whatever it is. No valid target at windup end: hold at fireLevel (windup done, "armed" stays), fire the first tick a target exists (windup not repeated; if the windup had been cancelled, it restarts).
  - `CRK-04` target (unchanged, decoded): candidates = buildings with an owner; score own colour -1, neutral level+1, other owner level+100; descending, first with level >= 1 and owner != tower owner. Highest-level enemy first, neutral only when no enemy qualifies, never own. Ties by building index (stable).
  - `CRK-05` projectile (unchanged, decoded): `entity` aim, fixed 40 ticks (2.0 s), on impact target level -> 0 (no ownership change; TW tweens over 1.0 s, we set at impact, recorded deviation), 3.0 blast kills enemy troops only. Tower is capturable; keeps charging/firing while owned by a non-neutral.
  - `CRK-06` params and design rationale: all per-map overridable (`fireLevel` 100, `resetLevel` 10, `chargePerTroop` 1, `growthPerSecond` 1.0, `windupMs` 3000); level files may override each; importer maps TW `scp/mcp/cc` -> ignored, recorded in `source.dropped` / deviation, defaults applied. Expected fill 10 -> 100: unfed (owned) ~90 s (about TW's AI tower ~75-90 s); fed by 1/2/3/4 houses ~43/28/21/17 s (a house ~1.1 troops/s each, growth +1/s on top). Intentional owner design deviation from TW (2026-10-28), recorded in Decisions and in the SP09 deviations ledger.
- **TW reference (decoded; NOT the shipped behaviour, kept for context):** `CaptureRocketTowerUiView`/`CaptureRocketTower`: charges while owner is not neutral; `chargingPower` starts at `scp`, every `cc` s (3.0 in all levels) adds the tower's current level; when `>= mcp` (levels 100-350, mostly 250/300) a ~0.2 s fill tween (`fillSliderDuration`) then `TryToAttack`; success `chargingPower -= mcp` (overflow carries); no target: hold/retry per tick. Owner change does not reset `chargingPower`. TW keeps this in a UI view. Target score, projectile and blast are identical to CRK-04/05.
- Tombstones for none; every rule needs `covers R-RKT-..`/`R-CRK-..` tests.

## Architecture
- **Base derivation (D7).** `rocket-tower` and `capture-rocket-tower` `extend` a shared base tower archetype (`tower`/`building-base`: level, owner, capture, footprint) and add `rocketTower` / `captureRocket` modules; rocket and capture shot `extend` SP04's `projectile-base` (aim path = base Path/line type used by `Aim`). Data-driven archetypes + modules, no TS class hierarchy.
- **Commands**: `Aim` pushes `{aimX,aimZ,aimSet}` into per-building columns (`rocketAimX/Z`, `rocketCd`, `rocketDisabledUntil`, `rocketFiredFlag`) hashed with buildings; capture rocket adds `windupTicks` (armed countdown, 0 = not armed) and `growMilli` (growth accumulator, milli-levels); no charge-points column because the building level is the charge. `canAim(player, from, x, z)` exported like `canDraw` for UI. Replays: commands are a closed union validated by the same schema, so new commands are additive; ruleset version in replay metadata gates old replays.
- **Phases**: new sub-step `7d rocket launches` after `7c`; impacts remain `7a`, so rockets launched at tick T land at T+20 in `7a`. Disable/charge timers decrement in 7d. Merge order with 07: 06 owns 7d and the row text; 07 adds `7e` if needed.
- **Projectile core extension (agree with 04, tiny, additive)**: `launch()` spec gains `travelTicks` override (rocket/capture rocket are fixed-time, not speed-based), `spawnType: 'tower'|'rocket'`, per-hit-kind effect table `{troop:'kill'|dmg, building:{levelDelta}|'setZero', element:'destroy'|'damage'}`, and an `onImpactBuilding` hook consumed by 06 for disable. If 04 already ships a superset, 06 only adds defs.
- **Aim storage**: point mode (`PRJ-02`); capture rocket uses `entity` mode so a building recaptured mid-flight still takes the hit; fizzles only if it no longer exists (never).
- **Determinism**: all integer; delay formula integer divide; no RNG; capture target = max score with ties to lowest building index (stable); capture growth is integer milli-levels (+50/tick at 1.0/s), windup is a 60-tick sim countdown, not UI.
- **Bots/identity**: rocket weight and `Aim` emission change TW AI output on rocket levels only; `BOT_VERSION` minor bump (expected 2.6.0; renumber to chain). Existing-20 `bots:golden` unchanged (asserted) since none has rt.
- **Web input**: gesture machine `own()` gate currently requires `drawsLines`; add a rocket branch: pointer-down on own rocket tower enters aim mode, preview shows aim reticle (ring r=1.15) and dashed path, release on ground -> `Aim`. Tap tower then tap ground also works (touch). Drag back onto tower, or tap tower while aimed -> `ClearAim`. Cutting strokes still skip aim paths. Feedback: reload ring (from `rocketCd`), stage pips, disabled state greyed with countdown, capture "armed" pulse during windup (no new meter UI; the level number is the meter), rejection text via `reasons.ts` (`disabled`, `out-of-bounds`).
- **Editor**: palette entries for rt/c_rt with `ds, lup, level` (rt) and `fireLevel, resetLevel, chargePerTroop, growthPerSecond, windupMs, level` (c_rt); rt shows default aim none; validation mirrors importer (c_rt not neutral-chargeable; warn neutral c_rt never fires).

## Decisions
| # | Decision | Choice | Alternatives | Why |
|---|---|---|---|---|
| 1 | Aim command | Point `Aim` + `ClearAim` | Reuse `DrawLine` with building target | TW aims at ground points; AI/clear semantics differ |
| 2 | Aim persistence | Persists until cleared | One-shot | `used` flag + AI retract implies persistent for humans (Risk 6) |
| 3 | Travel time | Fixed 20 ticks | Distance/speed | `rocketMoveTime 1.0` [decomp] |
| 4 | Capture | Level -> 0, not flip | Flip ownership | Decomp: no ownership change |
| 5 | Delay formula | Integer `480000/(L+120)` ms | Float | Exactly equals decoded formula, deterministic |
| 6 | AI weight | Content `rocketWeight` x10 int | Hard-coded by type | Decoded per-prefab constants |
| 7 | Blast ownership | Enemy-of-owner only (04 PRJ-03) | Hit friends | Research silent; see RESOLVED 7 |
| 8 | Version | RULES 3.5.0 minor, BOT minor | Major | Additive, old levels unaffected |
| 9 | Capture rocket charge model (owner, 2026-10-28) | Level is the charge: maxLevel 100, +1 per own troop, +1/s while owned, 3 s windup, fire, reset to 10; all params per-map overridable | Decoded TW `scp/mcp/cc` charge points | Owner design deviation from TW, intentional; simpler (no extra meter UI), feedable by houses, ~90 s unfed fill; recorded in the SP09 deviations ledger |
| 10 | Growth mechanism | Dedicated fixed-rate param `growthPerSecond` (milli-level accumulator, +1 per 20 ticks at 1.0) | Existing `grows` module | Independent of building-level growth tables; exact and integer |
