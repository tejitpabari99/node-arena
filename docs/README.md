# Documentation

Start with [mission](mission.md): it takes priority for product scope. The [game rules](specs/game-rules.md) are the detailed mechanics contract; authored content supplies tunable values.

| File or folder | Purpose | Audience |
|---|---|---|
| [mission.md](mission.md) | Product scope and documentation authority | Players and contributors |
| [architecture.md](architecture.md) | Workspace dependencies and campaign/PvP data flow | Contributors |
| [concepts/](concepts/README.md) | Determinism, content and online lifecycle | Contributors learning the system |
| [implementation/](implementation/README.md) | Authoring procedures and client/server implementation | Implementers and content authors |
| [reference/](reference/README.md) | Values, versions, fidelity and credits | Contributors and asset owners |
| [decisions/](decisions/README.md) | Accepted ADRs and deferred choices | Maintainers |
| [testing/](testing/README.md) | Gates, browser evidence and release checklist | Contributors and release owners |
| [specs/](specs/README.md) | Normative game rules and stable IDs | Designers and implementers |
| [operations/](operations/README.md) | Fly deployment, health, rollback and capacity | Server owner |
| [contracts/](contracts/README.md) | Pointers to generated schemas and wire types | Content/protocol consumers |
| [research/](research/README.md) | Historical research and teardown evidence | Investigators |
| [img/](img/README.md) | Recorded campaign screenshots | Repository readers |
| [agent_files/](agent_files/) | Branch designs, tasks and run/review records | Project agents and reviewers |

[tools/README.md](../tools/README.md) remains the canonical script/gate inventory. Research and branch records preserve point-in-time evidence; current product behaviour is documented in the maintained sections above.
